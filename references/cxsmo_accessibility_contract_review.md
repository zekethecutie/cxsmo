# C✦SMO Accessibility Contract Review

This review records the behavior verified directly from the current implementation. It distinguishes code-backed contracts from browser-assisted manual checks that remain appropriate before a public launch.

| Surface | Verified behavior | Implementation boundary |
|---|---|---|
| Primary navigation | The animated disclosure exposes menu semantics. `ArrowDown` opens and focuses the first destination; `ArrowUp` opens and focuses the last. Within the panel, `ArrowUp`, `ArrowDown`, `Home`, and `End` move between destinations. Outside-pointer dismissal closes the panel, while `Escape` closes it and restores focus to the trigger. | The menu is non-modal and does not trap `Tab`; following a destination preserves ordinary route navigation rather than returning focus to a disappearing trigger. |
| Route-aware tour | Tour start records the initiating element. The dialog moves initial focus to its Exit control, traps `Tab` and `Shift+Tab` within available controls, closes with `Escape`, and restores focus after returning to the origin route. | The tour is visitor-started; its visual cursor is explicitly presentational and never synthesizes user input. |
| Promotion popup | An enabled campaign popup records the previously focused element, moves focus to its close control, traps `Tab` and `Shift+Tab` among its controls, locks background scroll, closes with `Escape` or backdrop interaction, and restores focus when the prior element still exists. | The campaign is session-dismissible through browser storage and remains a fictional portfolio message rather than an offer or transaction surface. |
| Fit-guide dialog | The trigger exposes dialog state, the opened dialog receives focus on its close control, cycles `Tab` and `Shift+Tab` within its available controls, closes with backdrop click or `Escape`, and restores focus to the original trigger. | The dialog communicates that real garment measurements are not invented for the portfolio concept. |
| Product to bag | A browser-level keyboard audit opens a product directly, advances with `Tab`, activates size `L` with native `Enter`, then activates “Add to bag” with native `Enter`. It confirms the selected size, the added state, and the local header label `Bag 1`. | The audit clears `cxsmo-demo-state` before and after execution; it neither enters personal information nor leaves staged bag data behind. |
| Bag route | Browser-level keyboard audits stage one local line, reach “Preview checkout” using `Tab` and native `Enter`, then confirm checkout handoff; return to the bag route and activate its labelled remove control with native `Enter`; and open “Add order info,” tab through every input, enter only generic test values, and activate “Stage request preview” with `Enter`. They confirm empty-bag feedback, zero stored lines, and the visible “Request preview staged” state. | All audits clear `cxsmo-demo-state` afterward. The order-info values are generic test text, remain browser-local, and do not create any address, payment, order, or personal-data record. |
| Studio gate and controls | A browser-level keyboard audit confirms the portfolio code input receives initial focus, types the user-provided demo code, and activates the ordinary form path with `Enter`. A follow-up keyboard audit reaches the Categories module with `Tab` and `Enter`, focuses its category input, and adds the local-only “Orbit Lane” through `Enter`. | The audits remove `cxsmo-studio-unlocked` after execution. The gate and added lane remain declared portfolio demonstration state rather than authentication or a live store record. |
| Reduced motion | The site-wide reduced-motion sheet collapses animation and transition duration, while the route tour disables timed playback and retains an immediate, readable exit path. The morphographic Information Desk heading resolves as static text. | Visitors retain readable text and a direct exit rather than seeing hidden animation start states. |
| Hover audio | Sound stays browser-local and opt-in, with touch exclusion, global and per-element cooldowns, plus silent-control attributes for deliberately custom cues. | No sound plays without a user interaction. |

The current directed-tour layer also applies a full scroll lock while it is active. Wheel, touch-move, arrow-navigation, page-navigation, and home/end scroll events are suppressed, while `Tab`, `Shift+Tab`, buttons, and `Escape` retain their intended controls. The player’s large editorial copy sits inside a left-side blurred-black veil so the underlying route remains visible as a moving portfolio surface without competing with the readable route explanation.

The appearance control uses a two-second circular reveal anchored to the pressed toggle. Its overlay is the destination theme color only; no pixel field, red glow, or grid is rendered. The persisted theme class changes late in the reveal after the circle has covered the viewport, and reduced-motion preferences keep the theme change instant.

The browser-assisted checks complement, rather than replace, the code-backed contracts for navigation disclosure, fit-guide focus control, and bag/checkout simulation semantics. Before any public release, a keyboard-only person should still manually traverse the storefront, product controls, bag, checkout, and studio with their preferred browser and assistive technology.
